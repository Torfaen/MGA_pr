# 流水线工作流程总览

本文汇总 **`interface.json` 中的任务** 与 **`assets/resource/pipeline/` 下的管线文件** 的对应关系，便于 code review 与排障。运行时会在入口节点上叠加各任务所绑定的 `option.pipeline_override`。

**管线加载**：资源根目录为 `./assets/resource`；通常一次性加载 `pipeline/` 下多个 JSON（如 `战斗.json`、`强敌来袭.json`、`工具流水线.json` 等），节点名全局不可冲突。`工具流水线.json` 无独立 interface 任务，为战斗等管线提供子图/模板节点。

---

## 1. 任务总表（interface.json → 入口节点 → 主管线文件）

| 任务名 | 入口节点 | 主管线文件 | 任务选项（interface `option`） |
|--------|-----------|------------|----------------------------------|
| 启动游戏 | `启动游戏入口` | `启动游戏.json` | 无 |
| 启动加速器 | `启动加速器入口` | `启动加速器.json` | `加速器类型` |
| 日常 | `日常任务入口` | `每日任务.json` | `可选日常` |
| 材料本 | `材料本入口` | `材料本.json` | 无 |
| 战斗 | `战斗入口` | `战斗.json`（+ 已加载的其它 bundle 中的同名节点） | `故事选择`、`关卡选择`、`是否开启自动战斗`、`是否跳过隐藏boss战斗`、`自动战斗次数` |

---

## 2. 启动游戏（`启动游戏.json`）

- **作用**：仅 `StartApp` 拉起内置包，不做登陆/主界面识别。
- **主链路**：`启动游戏入口` → `启动游戏执行`（`com.bandainamcoent.gget_WW/com.unity3d.player.UnityPlayerActivity`）→ `启动游戏任务结束`（`StopTask`）。
- **改服**：编辑 `启动游戏执行` 的 `action.param.package`。

---

## 3. 启动加速器（`启动加速器.json`）

- **主链路**：`启动加速器入口` → `启动加速器执行`（`StartApp`）→ `加速器原生_锚点图标`（列表行图标，默认 `AccelGundamListIcon.PNG`）→ `加速器原生_点加速`（行内「加速」按钮，默认 `AccelBoostButton.PNG`，ROI 相对锚点 + `roi_offset`）。
- **选项 `加速器类型`（select）**：各 `case` 的 `pipeline_override` 覆盖 `启动加速器执行` 的 `package` 与 `加速器原生_点加速` 的模板。当前：**网易UU**（`com.netease.uu/.activity.LaunchActivity` + `加速器/UU_Boost.PNG`）、**腾讯手游加速器**（`com.tencent.cmocmna` + `加速器/TC_Boost.PNG`）。腾讯若仅包名无法启动，需 `adb shell cmd package resolve-activity --brief com.tencent.cmocmna` 后把组件名写回对应 `case` 的 `package`。
- **扩展**：新加速器可在 `cases` 中增加一项，并视 UI 增加对 `加速器原生_锚点图标` 的模板 override。

---

## 4. 日常（`每日任务.json`）

- **入口**：`日常任务入口` → 短步循环 `主画面检测`（OCR `RANK`），失败则 `返回主画面`（`强制返回主页`）后回跳。
- **选项 `可选日常`（checkbox）**：各子项通过 `pipeline_override` 打开对应分支（如商店、体力、战舰、开发、日常奖励、AP 消耗等），具体节点名见 `interface.json`。
- **结束**：通常经 `结束出口`（`StopTask`）。
- **评审**：新增分支须有回收路径（`jump_back` / `on_error`）；避免误判后直接 `StopTask`；短步 `timeout` 建议 2～5s 量级。

### 4.1 游戏唤醒（同一文件内的子入口）

- **interface**：任务「游戏唤醒」，`entry` = `开始唤醒`。
- **行为**：从 `开始唤醒` 起：OCR `START` 并点击，再进入 `唤醒失败` / `主画面检测` 等后续（与日常大图共用节点）。
- **用途**：从标题/启动画面进到主界面，**不是**「启动游戏」那种只拉包。

### 4.2 领取礼物盒（同一文件内的子入口）

- **interface**：任务「领取礼物盒」，`entry` = `领取礼物`。
- **行为**：OCR `礼物` 点击，后续衔接 `全部领取` 等（默认 `enabled` 等以 JSON 为准；与「可选日常」里开启礼物逻辑配合使用）。

---

## 5. 材料本（`材料本.json`）

- **入口**：`材料本入口`（与 `主页面检测` 等衔接，以 OCR `RANK` 等判定主界面）。
- **结束**：`任务结束出口`（`StopTask`）。
- **结构**：主界面判定 → 关卡/材料流程点击 → 结束出口。

---

## 6. 战斗与循环战斗（`战斗.json` + `工具流水线.json`）

- **`战斗入口`**：`next` 含 `战斗检测主画面` 与 `[JumpBack]主页返回`；不在主界面则 `强制返回主页` 后重试。
- **主线概要**：进关卡 → 主要关卡 → 故事/历史关卡分支 → `寻找HARD` → `关卡匹配`（`Custom: StageSelect`）→ 略过链或 `进入出击准备` → `出击任务` → 战前 auto/倍速等 → 战斗与多段结算 → `再次出击` / `退出关卡` 等。
- **`出击任务`**：**循环战斗**任务的入口，从已进出击上下文时接入上述中段。
- **`工具流水线.json`**：提供 HARD 关卡模板、OCR 辅助节点等，供 `战斗.json` 引用，无单独 interface 任务。
- **略过链要点**：`执行关卡略过` 后 `post_delay`；右下 `OK.png`；`体力不够并行兜底` 等（细节以 `战斗.json` 为准）。
- **结束**：略过成功常见 `战斗结算后结束`（`StopTask`）；另有 `战斗寻找错误退出`、`意外失败` 等硬出口。

---

## 7. 战斗V2（interface 嵌套选项）

- **入口仍为** `战斗入口`，管线文件仍为 `战斗.json` 等。
- **`战斗模式V2`（select）**：`主线` 嵌套原战斗多选项；`强敌来袭` 分支通过 `pipeline_override` 把 `战斗入口` 的 `next` 改为从 `强敌来袭：检测主画面` + 强敌主页返回切入 **强敌管线**（需已加载 `强敌来袭.json`）。

---

## 8. 强敌来袭（`强敌来袭.json` + `战斗.json`）

- **主链路（摘要）**：`强敌来袭：入口` → 检测主画面（`RANK`）→ 进关卡 → 事件 → 选「强敌来袭」→ `前往事件.PNG` → 强敌界面 → `选择机体`（模板）→ `关卡选择` → `强敌目标进入成功检测`（「选择关卡」）→ **二选一**：`略过关卡`（与 `战斗.json` 中略过链衔接）或 `强敌来袭：进入出击准备`（OCR「挑战」）→ `出击任务`。
- **选项 `强敌来袭目标`**：在 `interface.json` 的 `cases` 里覆盖 `强敌来袭：选择机体` 模板、`进入历史战斗` 开关、`寻找目标历史战斗_匹配` 模板等；含当期多机体与多条「历史战斗」机体，具体以 `interface.json` 为准。
- **排查**：OCR/ROI 与模板路径是否与分辨率一致；与 `战斗.json` 衔接节点名（`略过关卡`、`出击任务`）必须存在。

---

## 9. GP 任务（`自动刷金币.json`）

- **入口**：`金币任务入口`；另有内部 `批量开发入口` 等（以 JSON 为准）。
- **选项 `GP输入`**：`pipeline_override` 注入自定义动作参数（如 `GP_target`），与界面输入联动。

---

## 10. Code review 快速清单

- **入口**：`interface.json` 的 `entry` 在已加载 bundle 中是否存在且可达。
- **结束**：是否有明确 `StopTask` 或可回收循环，避免死循环或 silent hang。
- **循环**：`post_delay` / `timeout` / `rate_limit` 是否合理，避免空转刷日志。
- **识别**：模板 ROI、阈值；OCR `expected` 与分辨率。
- **Override**：`pipeline_override` 的节点名是否与管线一致（含跨文件节点）。
- **仓库卫生**：日志与缓存是否已被 `.gitignore` 排除（如 `logs/`、`debug/`、`agent/__pycache__/` 等）。

---

## 11. 维护建议

- 新增 interface 任务时：在上文 **任务总表** 增加一行，并增加或更新对应管线章节（入口 + 主链路 + 结束）。
- 改名节点时：同步 `interface.json` 的 `entry` / `pipeline_override` 与本文件。
- 若出现「约 20s 提前失败」：检查是否落回 `default_pipeline.json` 默认 `timeout`，或入口名与管线不一致。

---

## 12. 未纳入本仓库的管线

- **`机体强化.json`**：当前仓库的 `pipeline/` 下无此文件；若从其它分支或发行包合并，再补写「机体强化」任务与文档小节即可。
