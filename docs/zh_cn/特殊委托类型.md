# 角色要求：特殊委托类型判定

依据 `全部角色委托.xlsx` 的「全部委托」表，1046 条委托中有 290 条标题包含「特殊委托」。按「条件说明」归纳如下；条件类型的英文枚举与中文条件存在不一致，执行分类以条件说明为准。

| 达成条件 | 条数 | 分类与处理 |
| --- | ---: | --- |
| 交出带 `[N]`、`[R]`、`[SR]`、`[SSR]` 标签的机体 | 270 | 交付机体，进入对应角色的已有交付流程 |
| 交出 8600 CAPITAL | 3 | 调度资金，进入对应角色的已有资金交付流程 |
| 消耗 86 AP | 3 | AP 消耗，复用对应角色的请求出击流程，完成后报告 |
| 完成 3 或 6 次难度 HARD 的任一主要关卡 | 4 | HARD 主要关卡，记录尚未支持并跳过 |
| 完成 3、6 或 8 次任一事件关卡 | 4 | 事件关卡，记录尚未支持并跳过；条件排除战术训练，部分还排除来自教官的考验 |
| 击破 8 架单位（大师联盟除外） | 2 | 击破单位，记录尚未支持并跳过 |
| 获得 3 或 6 架单位 | 4 | 获得单位，记录尚未支持并跳过 |

「来自胡索的特殊委托1」（Excel 第 874 行）的条件是交出 `[R]夏柯`，应进入交付机体。第 993 行「来自利邦兹的特殊委托5」只有 `“[SSR]全装甲型0高达”`，没有「交出」，因此通过稀有度标签识别机体类别。标签匹配兼容全角括号，以及右括号被 OCR 识别成 `1`、`I`、`l` 的情况；AP 匹配排除 CAPITAL 内的字母组合。

左、中、右入口设置当前角色及点击坐标，然后进入统一的「点击当前角色」节点。它的 `next` 优先检查特殊委托，再检查五类普通要求。特殊委托只有一套判定节点：使用 OCR 识别标题区域 `[760, 100, 455, 95]` 内的「特殊要求」或「特殊委托」，然后在达成条件区域 `[760, 225, 455, 80]` 判定实际类别。条件区域避开报酬列表，避免奖励中的 CAPITAL 或机体标签影响分类。

强化部队、调度资金、交付机体、委托开发、请求出击和特殊委托全部共用各自的识别与处理节点。执行或跳过记录的参数使用 `"slot": "当前"`，由 `RoleRequirementTracker` 解析成实际位置。修改某一类的 OCR、入口、执行参数或跳过原因时只需修改一处。

选择角色时，`角色要求记录` 的 `select_slot` 操作同时配置共用点击节点的目标，以及共用返回节点的后续分支：左角色返回后检查中角色，中角色返回后检查右角色，右角色返回后汇总。成功执行仍进入原来的角色列表检查流程；交付机体、委托开发和请求出击的失败或软跳过共用返回节点，强化部队和调度资金保留原来的失败处理。无法识别特殊委托条件时，记录「特殊委托内容无法判定」并返回角色列表。

当前角色在流程重置时清空；角色选择或动态配置失败时不保留上一个位置。独立调用共用处理节点前必须先选择角色；没有当前位置的执行或跳过记录会失败，避免把结果记到错误的角色。共用点击节点默认关闭，由选择角色操作设置坐标后启用。

执行结果同时检查任务详情是否存在和 `status.succeeded`，避免将返回了失败详情的子任务记成完成。运行 `python tools/CI/check_role_requirement_flow.py` 可用本地模拟控制器验证三种位置下的点击范围、完成记录、失败记录、软跳过、普通类别不明及特殊委托返回分支；该检查不连接游戏。

HARD 主要关卡、事件关卡、击破单位和获得单位不能直接套用当前固定关卡的请求出击流程或委托开发流程，需要各自的执行策略。AP 消耗复用请求出击的现有次数上限与体力处理，本次没有更改这些策略。
